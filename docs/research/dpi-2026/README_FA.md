# پایگاه دانش سانسور شبکه و DPI برای Hawal

آخرین بازبینی: ۱۲ شهریور ۱۴۰۵ / ۳ سپتامبر ۲۰۲۶

این پوشه مرجع فنی پروژه برای تحلیل اختلال شبکه و طراحی نسل بعدی Hawal Core است. یافته‌ها عمداً به سه گروه تفکیک شده‌اند:

- **مشاهده‌شده:** نتیجه‌ای که اندازه‌گیری یا مقالهٔ معتبر مستقیماً گزارش کرده است.
- **استنباط:** توضیح محتملی که از چند مشاهده نتیجه گرفته شده، اما مستقیماً اثبات نشده است.
- **فرضیهٔ آزمایشی:** ایده‌ای که باید فقط روی زیرساخت تحت کنترل خودمان آزمایش شود.

## قواعد استفاده در پروژه

1. هیچ قابلیت تازه‌ای صرفاً به دلیل وجود در Xray، GOST یا ابزار دیگر «موثر» تلقی نمی‌شود.
2. هر تصمیم Wire Protocol باید به یک تهدید ثبت‌شده و یک آزمون بازتولیدپذیر وصل باشد.
3. نتیجهٔ یک ISP، یک روز یا یک پورت به کل ایران تعمیم داده نمی‌شود.
4. امنیت رمزنگاری از استتار ترافیک جداست؛ برای رمزنگاری از طرح‌های استاندارد استفاده می‌کنیم.
5. آزمایش فعال فقط میان IPها و سرورهای تحت کنترل انجام می‌شود.
6. راهبردهایی که باعث مصرف یا اختلال برای شبکه‌های ثالث می‌شوند وارد محصول نمی‌شوند.
7. هر ادعای مربوط به «عبور از فیلتر» باید تاریخ، شبکه، جهت، پورت، Transport و فایل Capture داشته باشد.

## نتیجهٔ فعلی برای Hawal

نسخهٔ فعلی Hawal Core به علت Magic ثابت `HWL1`، هدر فریم آشکار، پاسخ Probe ثابت و Session طولانی، برای محیط دارای DPI تطبیقی مناسب نیست. اصلاح یک فیلد کافی نیست؛ نسل بعد باید امنیت Session، Multiplex، Carrier و کنترل تطبیقی را به ماژول‌های مستقل تبدیل کند.

کارکردن Paqet در مسیری که Socket-based tunnelها کار نمی‌کنند، یک شاهد محلی ارزشمند است، اما هنوز علت را ثابت نمی‌کند. Capture هم‌زمان دو سمت باید مشخص کند تفاوت ناشی از Wire Image، رفتار TCP سیستم‌عامل، پورت، Direction، Packet Loss یا سیاست دیگری است.
